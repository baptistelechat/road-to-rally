# LRN-20261103211811-4 — Pendant la ré-analyse, l'axe est celui de l'ancien tracé

**Pattern observé** : `useTraceAnalysis` passe `analyzing: true` sans vider `analysis`. Tant que le worker n'a pas répondu, `analysis.axis` appartient au tracé d'avant alors que `history.present` est déjà le nouveau. Les chicanes du joueur projetées sur cet axe (`nearestIndex`) tombent avant les lignes, et `formatKm` les ramène toutes au km 0,00 : d'où des alertes « 0 m entre les deux » identiques et des clés React dupliquées.

**Contexte** : warning « Encountered two children with the same key » dans le terminal de dev, alors que la garde `axisReady` existait déjà.

**Application future** : tout ce qui se calcule à partir de `analysis` et du tracé courant (alertes, km, positions) attend `!analyzing`, pas seulement `analysis != null`. Une liste de messages se clé par rang, jamais par le texte seul.
