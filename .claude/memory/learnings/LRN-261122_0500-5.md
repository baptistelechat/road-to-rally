# LRN-261122_0500-5 — Empreinte sur octets de floats : -0 casse après JSON

**Pattern observé** : Une empreinte calculée sur les octets d'un `Float64Array` distingue `-0` de `0` (bits de signe différents), alors que `JSON.stringify(-0)` écrit `"0"`. Une donnée qui contient un `-0` change donc d'empreinte une fois écrite puis relue, alors que son JSON est identique octet pour octet et qu'une comparaison `===` ou `deepEqual` ne voit aucune différence. Diagnostic : chercher `Object.is(v, -0)` dans les valeurs. Correctif à la source du hash : `values.map((v) => v + 0)` sur les tableaux flottants (`-0 + 0 === +0`).

**Contexte** : `fingerprint.check.ts` : `stageHash(spéciale relue)` différait de `stageHash(spéciale générée)`. Le décor IGN contenait quelques `-0` (hauteurs et caps d'arbres). Corrigé dans `src/geo/stageHash.ts`.

**Application future** : Tout hash ou checksum binaire sur des nombres qui transitent par du JSON doit normaliser `-0`. Devant un « même JSON, hash différent », penser au `-0` avant de chercher un champ manquant.
