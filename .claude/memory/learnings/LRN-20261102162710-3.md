# LRN-20261102162710-3 — Changer PIPELINE_VERSION impose pnpm bake:stages

**Pattern observé** : `PIPELINE_VERSION` entre dans l'empreinte des spéciales. Tant que `public/stages` n'est pas régénéré, `fingerprint.check.ts` et `geo.check.ts` échouent, alors que les checks du sujet (`chicanes`, `editor-flow`) passent.

**Contexte** : Passage à la version 6 pour la hauteur des chicanes. L'échec n'est apparu qu'à la suite complète, juste avant le push, et a coûté deux passages de plus.

**Application future** : Lancer `pnpm bake:stages` dans le même commit que le changement de version, et ajouter `fingerprint geo` aux checks de la tâche.

**Ajout (2026-11-03)** : L'inverse coûte aussi : un changement du pipeline sans incrémenter la version laisse le cache IndexedDB (clé `gpx:PIPELINE_VERSION`) resservir l'ancienne spéciale, et la correction semble ne rien faire en jeu. Toujours incrémenter, puis `pnpm bake:stages`.
