# LRN-261104_2153-7 — Agents parallèles : fichiers chauds gardés par l'orchestrateur

**Pattern observé** : Trois agents ont livré les stories 4.1 à 4.5 en parallèle sans conflit, puis deux autres les retours de playtest. Les fichiers que toutes les stories touchent (`useGameLoop.ts`, `hudStore.ts`, `Hud/index.tsx`, `Game.tsx`) étaient interdits aux agents : chacun renvoyait une section « Intégration » avec le code exact, et l'orchestrateur branchait tout en une passe. Les points de contact étaient écrits dans les briefs avant le lancement (`sim.lap.currentMs()` vaut `null` avant le GO et compte les pénalités, `StageRecord.ghost` à typer par l'agent fantôme). Aucune commande lourde dans les agents : lint et build une seule fois à la fin.

**Contexte** : Epic 4, 04/11/2026. Deux agents ont aussi signalé d'eux-mêmes un doublon à résorber à l'intégration (`formatLap`).

**Application future** : Avant un fan-out sur ce projet, lister les fichiers chauds et les garder pour soi ; écrire les contrats de données dans chaque brief ; demander une section « Intégration » et les choix à valider au volant. Voir aussi GLRN-360 (fichiers disjoints, grep post-edit).
