# LRN-261104_1546-4 — Reproduire un tracé éditeur : /api/diag puis stageGpx

**Pattern observé** : le brouillon de l'éditeur vit dans `localStorage['rally-editor-draft']`. Depuis un onglet sur `localhost:3000`, `fetch('/api/diag', { method: 'POST', body: localStorage.getItem('rally-editor-draft') })` l'écrit dans `diag/` (ignoré par git, dev seulement). En Node via `tsx`, `stageGpx(draft)` (`src/editor/store.ts`) rend le GPX exact, et `analyzeTrace(gpx, { widthsByHighway: draft.segments })` reproduit l'alerte de l'éditeur. Sans `widthsByHighway`, toutes les largeurs valent 5 m et un contact entre routes peut disparaître.

**Contexte** : sortie de `javascript_tool` tronquée vers 1 000 caractères, impossible d'y lire le brouillon (15 Ko) directement.

**Application future** : pour tout bug d'analyse signalé dans l'éditeur, passer par ce chemin plutôt que reconstruire un tracé synthétique à la main.
