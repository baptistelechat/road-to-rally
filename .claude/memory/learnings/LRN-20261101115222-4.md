# LRN-20261101115222-4 — Pièges de l'API altimétrie de l'IGN

**Pattern observé** : `zonly` doit être la chaîne `"true"` car un booléen JSON renvoie une erreur 400. Une requête accepte 5000 points et en refuse 5001. Hors couverture, la réponse est un 200 avec l'altitude `-99999`. Le CORS est ouvert.

**Contexte** : Testé le 2026-11-01 sur `POST https://data.geopf.fr/altimetrie/1.0/calcul/alti/rest/elevation.json` avec la ressource `ign_rge_alti_wld`, en cadrant la story 2.2.

**Application future** : Traiter `-99999` comme une erreur, sinon une altitude absurde passe sans bruit. Découper les requêtes à 5000 points et les envoyer une par une : les en-têtes de débit sont ambigus (`x-ratelimit-limit-second: 1` et `ratelimit-limit: 5`).
