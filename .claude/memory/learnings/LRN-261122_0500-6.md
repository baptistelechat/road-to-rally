# LRN-261122_0500-6 — `cat > fichier` sans entrée bloque la commande sur stdin

**Pattern observé** : Dans une commande Bash enchaînée, un `cat > fichier` sans heredoc ni redirection d'entrée attend stdin indéfiniment : toute la commande reste bloquée jusqu'au délai de 2 min, passe en arrière-plan, et les étapes suivantes (création du vrai script, exécution, nettoyage) ne s'exécutent jamais. Le symptôme ressemble à un script lent. Écrire les fichiers temporaires avec l'outil `Write`, et n'utiliser `cat` qu'avec `<<'EOF'`.

**Contexte** : Script de diagnostic de `pace-note-cue` : un `cat > "$TMPDIR/dbg.ts"` resté vide a bloqué la commande, Baptiste a demandé « tu es bloqué ? ». Même session : une sortie de check filtrée par `| grep | tail` n'affiche rien avant la fin ; rediriger vers un fichier log permet de lire l'avancement.

**Application future** : Relire chaque `cat >` d'une commande avant de la lancer. Pour un long check, écrire dans un log (`> run.log 2>&1`) plutôt que de filtrer en direct.
