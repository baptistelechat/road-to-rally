# LRN-20261103202354-4 — Un check lancé seul avec tsx ne vérifie rien

**Pattern observé** : Les fichiers `scripts/checks/*.check.ts` exportent une fonction `default` que seul `scripts/check-determinism.mts` appelle. `npx tsx scripts/checks/pace-note-cue.check.ts` charge le module et sort en code 0 sans rien exécuter. Ça m'a donné un faux « le timing passe », démenti ensuite par la suite complète. Un fichier temporaire qui importe le check bute sur le top-level await (sortie CJS de tsx).

**Contexte** : Allongement de la phrase des enfilades : le check de timing paraissait vert seul, puis échouait de 0,2 s dans `pnpm check:determinism`.

**Application future** : Valider uniquement par `pnpm check:determinism`, quitte à attendre plusieurs minutes. Un code de sortie 0 sans aucune ligne `ok` ni `FAIL` n'est pas une réussite.

**Complément (2026-11-03)** : Un nouveau fichier de check sans `export default` fait échouer toute la suite : le lanceur appelle `mod.default()`. Pour exécuter quelques checks en quelques secondes, un lanceur `.mts` temporaire à la racine fonctionne : `const mod = await import(pathToFileURL(f).href); await mod.default();` pour chaque fichier passé en argument. Il affiche `ok` par check, ce qui évite le faux vert.
