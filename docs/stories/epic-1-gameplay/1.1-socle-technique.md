# Story 1.1 : Socle technique et boucle à pas fixe

**Statut : validé**

## Objectif

Une page plein écran affiche une boîte qui tombe sur un sol, et la simulation tourne à 60 Hz quel que soit le nombre de FPS.

## À faire

- `git init`, projet Next.js 16 avec pnpm : App Router, TypeScript strict, Tailwind, ESLint, dossier `src/`.
- Dépendances : `three`, `@react-three/fiber`, `@react-three/drei`, `@dimforge/rapier3d-deterministic-compat`, et `tsx` en développement pour le script de vérification.
- `src/app/page.tsx` reste un Server Component et affiche un Client Component, qui charge le jeu via `next/dynamic` avec `ssr: false`.
- Séparer dès le départ :

| Dossier       | Contenu                      | Règle                                                       |
| ------------- | ---------------------------- | ----------------------------------------------------------- |
| `src/sim/`    | Monde Rapier, voiture, tracé | TypeScript pur : ni React, ni rendu, doit tourner dans Node |
| `src/render/` | Scène React Three Fiber      | Lit l'état de la simulation, ne l'écrit jamais              |
| `src/input/`  | Clavier, manette             | Produit une entrée par pas de simulation                    |

- Boucle à accumulateur : pas fixe de 1/60 s, plafond de pas par image pour éviter la spirale de la mort après un onglet en arrière-plan.
- Rendu interpolé entre les deux derniers états de simulation (position et rotation).

## Critères d'acceptation

- [x] La boîte tombe et se pose à l'identique à 30, 60 et 144 FPS (bridage testable via un `sleep` de debug).
- [x] Revenir d'un onglet resté en arrière-plan ne fige pas et ne téléporte pas la scène.
- [x] Un script `pnpm check:determinism` exécute 600 pas deux fois dans Node et compare les positions au bit près.
- [x] `pnpm lint` et `pnpm build` passent.

## Pièges

- R3F 9 demande React `>=19 <19.4` : vérifier la version installée.
- `ssr: false` n'est accepté que dans un Client Component. Three.js, R3F et Rapier ne doivent jamais être importés côté serveur.
- Le Strict Mode de React exécute les effets deux fois en développement : créer le monde Rapier dans un effet et le libérer au nettoyage avec `world.free()`, sinon on se retrouve avec deux simulations.
- Turbopack n'implémente pas `fetch(new URL(…, import.meta.url))` (GLRN-294) : ne charger aucun asset de cette façon. Le paquet `-compat` y échappe car son WASM est embarqué, à confirmer dès le premier `pnpm build`.
- Le déterminisme entre machines n'est pas garanti par ce test. Il sera vérifié navigateur contre Node en story 1.4, avec le contrôleur de véhicule : aucune source consultée ne le confirme pour ce composant.
- Les paquets `-compat` embarquent le WASM : initialiser avec `await RAPIER.init()` avant toute création de monde.
