# Story 4.4 : Meilleur temps local

**Statut : code livré, jugement au volant attendu**

## Objectif

Garder sur la machine le meilleur temps de **chaque** spéciale, avec ses temps de passage, et plus tard son fantôme. **Une spéciale dont le tracé change repart sans record.**

## Identité d'une spéciale

`GameMap.recordId`, dans `src/game/maps.ts` :

| Carte                         | `recordId`                              |
| ----------------------------- | --------------------------------------- |
| `track`, `road`, `mountain`, `notes` | l'identifiant de la carte        |
| Spéciale importée ou créée dans l'éditeur | `StageData.hash`, l'empreinte du tracé |

L'empreinte (`stageHash`) couvre points, largeurs, terrain, chicanes et version du pipeline : modifier une spéciale dans l'éditeur change son identité, conformément à BDR-20261102162710-1 (la rouler à nouveau remplace son tracé). La même spéciale importée deux fois partage son record. Les cartes livrées n'ont pas d'empreinte dans leur JSON : leur record suit l'identifiant, à réévaluer si elles sont régénérées.

## Stockage

- Clé `rally:stage-record:<recordId>`, valeur JSON versionnée :

```ts
interface StageRecord {
  version: 1;
  totalMs: number; // pénalités comprises
  splitsMs: readonly number[];
  date: string; // ISO
  ghost?: unknown; // story 4.5
}
```

- **Lecture** : une valeur abîmée ou d'une autre version compte comme absente. Sans record, l'ancienne clé `bestLapKey` (`rally:best-lap-ms`, `…:road`, `…:<hash>`) est reprise comme temps seul, sans intermédiaires.
- **Écriture** : seulement pour un nouveau record (`isNewRecord`), car le fantôme pèsera des centaines de Ko. Quota dépassé : le record est réécrit sans fantôme plutôt que perdu ; l'ancien record reste intact si rien ne passe.
- Stockage bloqué (navigation privée, cookies refusés) : lecture `null`, écriture ignorée, le record vit le temps de la session.

## Ce qui est livré

- `src/game/stageRecords.ts` : `stageRecordKey`, `readStageRecord`, `isNewRecord`, `writeStageRecord`.
- `recordId` sur chaque `GameMap`, `bestLapKey` gardé pour la reprise.

## Critères d'acceptation

- [ ] Deux spéciales créées dans l'éditeur gardent chacune leur record.
- [ ] Modifier le tracé d'une spéciale puis la rouler à nouveau : pas de record.
- [ ] Le record du circuit enregistré avant cette story s'affiche toujours.
- [ ] Un temps plus lent n'écrit rien.
- [ ] Navigation privée : le jeu tourne, le record vit la session.
- [ ] `pnpm lint` et `pnpm build` passent.

## Pièges

- Le temps comparé inclut les pénalités : une remise en piste rend un record plus difficile, c'est voulu.
- `localStorage` est synchrone : n'écrire qu'à l'arrivée, jamais pendant la course.
